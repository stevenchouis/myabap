# 講義 12：列印排版與頁面規劃

> 對應練習：[ex12](../ex12_print_layout.md)｜答案程式：`ZR_TR12_PRINT_LAYOUT`

## 本講重點

- 紙本報表的規格思維：點矩陣印表機、行寬與行數怎麼定
- `REPORT` 附加項：`NO STANDARD PAGE HEADING` / `LINE-SIZE` / `LINE-COUNT n(m)`
- `WRITE` 精確排版：位置、寬度、對齊、`CURRENCY`
- `ULINE` / `SKIP` / `NEW-PAGE`、`sy-pagno`
- `TOP-OF-PAGE` 頁首與 `END-OF-PAGE` 頁尾的搭配

## 1. 先懂紙，再談排版

傳統表單（出貨單、對帳單）常印在**點矩陣印表機＋連續報表紙**上，規格是排版的前提：

| 規格 | 常見值 | 由來 |
|---|---|---|
| 行寬 | 132 字元（寬機）／80 字元（窄機） | 10 CPI 字距下紙寬決定 |
| 每頁行數 | 66 行 | 11 吋紙 × 6 LPI |
| 實用行數 | 65 行（留 1 行安全邊界） | 對應 SAP 列印格式 `X_65_132`（SPAD 維護） |

### 買紙時看到的規格：80 行、132 行、全頁、中一刀

台灣文具行賣的連續報表紙，品名通常長這樣：「電腦報表紙 9.5×11×1P（80行）中一刀」。每一段的意思：

| 品名上的字 | 意思 |
|---|---|
| `9.5×11` | 紙寬 × 紙長，單位英吋。**寬度含兩側的撕邊孔條**，實際能印的寬度比較窄 |
| `80行`、`132行` | **一行能印幾個字**（正常字距 10 CPI），也就是「欄數」，**不是**一頁幾行。這跟 ABAP 的 `LINE-SIZE` 是同一件事，跟 `LINE-COUNT` 無關，不要搞混 |
| `1P`、`2P`、`3P` | 聯數：幾張疊在一起的複寫聯（1P＝單聯） |
| `全頁`（全張） | 11 吋長的一頁中間沒有撕線 |
| `中一刀` | 11 吋長的一頁**中間多一條撕線**，可以撕成上下兩張 9.5×5.5 吋 |
| `中二刀` | 中間有**兩條**撕線，一頁撕成三張 |
| `雙切` | 兩側的孔條可以撕掉 |

常見的兩種寬度：

| 紙張 | 一行幾個字 | 對應的程式設定 |
|---|---|---|
| 9.5×11 吋（80 行，窄機） | 80 | `LINE-SIZE 80`，格式 `X_65_80` |
| 14 7/8×11 吋（132 行，寬機） | 132 | `LINE-SIZE 132`，格式 `X_65_132` |

**中一刀、中二刀改變的是「一張單據的長度」**。行數用同一個公式算（6 LPI，每吋 6 行）：

| 撕法 | 每一張的長度 | 每一張可印的行數 |
|---|---|---|
| 全頁 | 11 吋 | 66 行 |
| 中一刀 | 5.5 吋 | 33 行 |
| 中二刀 | 約 3.67 吋 | 22 行 |

所以單據如果要印在中一刀的「半張」上（例如小張的出貨單、收據），程式的頁長就不能再用 65 行，要照半張來規劃。常見兩種做法：

1. **一張單據一頁、頁長 33 行**：程式寫 `LINE-COUNT 33`，並請 Basis 用交易碼 **SPAD** 建一個頁長 33 行的自訂列印格式（標準格式裡沒有 33 行的，見下方說明），印表機的「頁長」設定也要調成 5.5 吋，換頁才會剛好停在撕線上。
2. **頁長維持 66 行，一頁排兩張單據**：第一張從第 1 行開始，第二張用 `SKIP TO LINE 34` 從下半張開始（本講第 2 節的 `SKIP TO LINE`）。印表機設定不用改，但程式要自己控制每半張的行數。

用哪一種要看印表機和單據量，但**規劃版面的第一步永遠是先問清楚用哪一種紙**，行寬和頁長都由紙決定。

#### 自訂格式由誰建、在哪建：交易碼 SPAD

列印格式由 Basis 在交易碼 **SPAD**（Spool Administration，列印管理）維護，程式設計師通常沒有權限，也不該自己改。SPAD 裡跟「紙」有關的設定有兩種，**用途不同，不要搞混**：

| 設定 | 定義什麼 | 給誰用 | 本系統的例子（2026-09-30 查 `TSP1D`／`TSP08`） |
|---|---|---|---|
| **清單格式**（類型 L） | 一頁幾行 × 一行幾字 | ABAP 清單報表（`WRITE`，本講的主題） | 標準 `X_65_132`＝65×132；客戶自建 `Z_65_256`、`Z_65_360`（寬報表用） |
| **紙張格式**（Page Format）＋ 表單用格式（類型 S） | 紙的實際尺寸（公釐、英吋） | Smartform／SAPscript 表單 | `ZLTER2`，說明文字就是「**中一刀**」：寬 215 mm × 高 140 mm；另有直式的 `ZLETTERH` 140 × 215 mm |

`ZLTER2` 的高度 140 mm 約等於 11 吋的一半（5.5 吋 ≈ 139.7 mm），正好是中一刀的半張，代表公司已經有人為了中一刀建過格式。**但它是給 Smartform／SAPscript 表單用的**：表單在自己的頁面設定指定這個紙張格式，就能印在中一刀半張上。

清單報表（`WRITE` 輸出）要印在中一刀上，需要的是另一種 **L 類型、頁長 33 行的清單格式**，本系統目前沒有，要請 Basis 另外建。常見的命名習慣是照標準格式的規則，例如 `Z_33_80`（33 行 × 80 字），客戶自建格式以 `Z` 開頭。建好後要在 SPAD 指派給實際要用的印表機（Device Type），列印對話框的 Format F4 才會出現。

> 格式與紙張的定義可以用 `SELECT` 查表確認：`TSP1D`（格式：`PAPART` 名稱、`TYPE` L／S、`OUTROWS`／`OUTCOLUMNS` 行數／欄數）、`TSP08`（紙張格式的寬高）、`TSP1T`（說明文字）、`TSP06A`（格式指派給哪些 Device Type）。

> 規格來源：台灣報表紙廠商的產品說明（如 9.5×11 為 80 行、14 7/8×11 為 132 行；中一刀撕開為 9.5×5.5 吋）。中一刀／中二刀的實際撕線位置以手上的紙為準。

所以課程範例的固定開場白是：

```abap
REPORT zr_tr12_print_layout NO STANDARD PAGE HEADING
                            LINE-SIZE 132
                            LINE-COUNT 65(3).
```

| 附加項 | 意義 |
|---|---|
| `NO STANDARD PAGE HEADING` | 關掉系統預設頁首（程式名那行），自己用 TOP-OF-PAGE 畫 |
| `LINE-SIZE 132` | 每行 132 字元，超過的 WRITE 內容折到下一行 |
| `LINE-COUNT 65(3)` | 每頁 65 行，其中**保留末尾 3 行**給頁尾（END-OF-PAGE） |

> `(3)` 這個保留區是 END-OF-PAGE 的開關：**沒有保留行數，END-OF-PAGE 永遠不觸發**——最常見的「頁尾怎麼不出來」原因。

### 1.1 超過 132 欄的寬報表：LINE-SIZE 要對得上列印格式

實務上常看到比 132 更寬的寫法，例如某支傳票清單程式：

```abap
REPORT zrfi0004 NO STANDARD PAGE HEADING
                LINE-SIZE 203
*               LINE-COUNT 65(6).
                LINE-COUNT 65(0).
```

**203 不是某種印表機的標準寬度**。點矩陣寬機用一般字距（10 CPI）一行約 132 字；要印得更寬，靠的是**壓縮字（約 17 CPI）或雷射印表機 A4／A3 橫印**，印得下的字數因此可以到 200 甚至 255 字。203 通常是開發者依自己的欄位（中文字一個佔 2 欄，見 2.1）一欄一欄加出來的數字。

SAP 列印時要挑一個**寬度 ≥ LINE-SIZE** 的列印格式（SPAD 維護）。本系統實際存在的標準格式如下：

| 列印格式 | 每頁行數 × 每行字數 | 典型用途 |
|---|---|---|
| `X_65_80` | 65 × 80 | 窄機、直式 |
| `X_65_132` | 65 × 132 | **點矩陣寬機標準**（本課程採用） |
| `X_65_200` | 65 × 200 | 壓縮字／雷射橫印 |
| `X_65_255` | 65 × 255 | 壓縮字／雷射橫印，傳統清單的最大寬度 |
| `X_44_120`、`X_58_170`、`X_70_200`、`X_90_120` | 行數、寬度的其他組合 | 依印表機另外設定 |

套到上面的例子：`LINE-SIZE 203` 比 `X_65_200` 寬 3 欄，放不進去，要用 **`X_65_255`** 才印得完整。**建議寬報表直接取格式的寬度**（200 或 255），不要取 203 這種夾在兩個格式中間的數字。畫面上的清單不受影響，差別只出現在實際列印時。

另外兩點：

- `LINE-COUNT 65(0)`：保留 0 行，**END-OF-PAGE 永遠不會觸發**，效果跟不寫 `(m)` 一樣。從被註解掉的 `65(6)` 看得出來，原本有 6 行頁尾，後來被拿掉了。
- 寬報表在螢幕上要左右捲動才看得完（如上面傳票清單的畫面底部有橫向捲軸），欄位多到 200 欄以上時，改用 ALV（講義 9）通常更好用。

### 1.2 實際要印到某台印表機：先查它支援哪些 Format

工廠常見的大型印表機，大多是**寬機點矩陣**（如 Epson LQ-2xxx）或**行式印表機**（Line Matrix，如 Printronix、TallyGenicom）。兩者都用 15 吋寬的連續報表紙，可以印多聯複寫；正常字距一行約 136 字，壓縮字約 230 字。在 SAP 裡通常對應 `X_65_132` 或 `X_65_255`。印條碼、貼紙的標籤機（如 Zebra）則屬於另一套機制（Smartform／ZPL），不適用本講的清單列印。

**光看機器判斷不出它用哪個 Format。** Format 是 SPAD 依那台印表機的 **Device Type（裝置類型）** 設定的，不同 Device Type 支援的清單也不同。查法有兩種：

1. **列印對話框（最簡單）**：隨便跑一支清單報表 → 列印 → Output Device 選那台印表機 → 在 **Format** 欄位按 F4。清單裡只會出現這台印表機支援的格式。
2. **SPAD（通常要 Basis 權限）**：Output Devices → 找到那台印表機，記下 Device Type → 到 Device Types 開啟該類型 → **Formats**，就是支援的格式清單。

以本課程的 Demo 系統為例：前端印表機（Device Type `SWINCF`）支援 `X_65_80`／`132`／`200`／`255`，但範例印表機 `LP01`（HP LaserJet 類型 `HPLJIIID`）**沒有 `X_65_200`**。所以 1.1 的 `LINE-SIZE 203` 能不能印，還要看目標印表機有沒有 `X_65_255`。

查到格式後，**REPORT 參數直接照格式名稱的數字寫**。格式名稱的規則是 `X_行數_寬度`：

| 印表機支援的格式 | REPORT 參數 |
|---|---|
| `X_65_132` | `LINE-SIZE 132  LINE-COUNT 65(m)` |
| `X_65_255` | `LINE-SIZE 255  LINE-COUNT 65(m)` |
| `X_90_120` | `LINE-SIZE 120  LINE-COUNT 90(m)` |

- `m` 是頁尾保留行數，沒有頁尾就不寫 `(m)`。
- **寬度優先用 132**，正常字距最好讀；欄位真的放不下，再改用 255（代價是改成壓縮字、字會變小）。
- LINE-SIZE 可以比格式窄，但不能比它寬，寬了會被截斷。
- 報表如果固定只印到某台印表機，可以在程式裡用 `GET_PRINT_PARAMETERS` 的 `LAYOUT = 'X_65_132'` 把格式寫死，使用者就不用每次自己選。

### 1.3 正常字距還是壓縮字：由 Format 決定，不是程式

**程式裡沒有任何「切換成壓縮字」的指令**，ABAP 清單只管「一行幾個字、一頁幾行」。字距是這樣決定的：

1. 程式的 `LINE-SIZE`／`LINE-COUNT` 決定清單的大小。按列印時，系統會依清單寬度**帶出一個預設 Format**（例如寬 132 帶 `X_65_132`），使用者也可以在對話框改選。
2. 在 SPAD 裡，每個「Device Type × Format」組合都設定了**送給印表機的初始化控制碼**（Printer Initialization）。點矩陣印表機切換成 17 CPI 壓縮字，就是靠 `X_65_255` 這類格式內的控制碼達成的；`X_65_132` 則維持正常 10 CPI。
3. 前端／Windows 驅動印表機（如 `SWINCF`）沒有控制碼這一層，而是由 SAP 依格式寬度自動縮放字體，效果一樣：選 255 字寬就印得比較小。

所以程式只是**間接**影響字距：LINE-SIZE 決定系統帶出哪個 Format，真正切換字距的是 Format 的設定。某個格式印出來字距不對，要請 Basis 檢查 SPAD 裡該 Device Type 的 Format 設定，改程式沒有用。

## 2. WRITE 精確排版

完整格式：`WRITE [AT] /位置(寬度) 資料 [對齊/格式選項].`

```abap
LOOP AT gt_items INTO gs_item.
  WRITE: /1  '|', 2(6)   gs_item-itemno,
          9  '|', 10(20) gs_item-name,
          31 '|', 32(10) gs_item-qty,
          43 '|', 44(14) gs_item-price  CURRENCY 'USD',
          59 '|', 60(16) gs_item-amount CURRENCY 'USD',
          77 '|'.
ENDLOOP.
```

| 寫法 | 意義 |
|---|---|
| `/1` | 換行後從第 1 欄開始 |
| `10(20)` | 從第 10 欄開始、寬度 20 |
| `(20)`（無位置） | 接目前位置，寬度 20 |

每欄位固定「起始欄＋寬度」，配合頁首同座標的欄位標題，直欄就會對得筆直——這是點矩陣報表排版的全部秘密：**畫一張欄位座標表，頁首、明細、頁尾都照表寫**。

**位置、寬度也可以用變數**，但要加 `AT`：

```abap
DATA: gv_pos TYPE i VALUE 5,
      gv_wid TYPE i VALUE 10.
WRITE AT /gv_pos(gv_wid) gs_item-name.       " 從第 5 欄起、寬 10
```

講義 13 的實戰案例 ZRFI0004 把整張欄位座標表寫成一個結構，每個欄位的寬度都是一個元件，頁首、明細、合計列都寫 `WRITE AT (t_optfm-hkont) ...`。要調整某一欄的寬度，只要改結構裡的一個 `VALUE`，所有列會一起變：

```abap
DATA: BEGIN OF t_optfm,
        hkont TYPE i VALUE 30,     " 會計科目欄寬
        kostl TYPE i VALUE 10,     " 成本中心欄寬
        ...
      END OF t_optfm.

WRITE: AT /01(t_optfm-hkont) '會計科目' CENTERED,     " 頁首
       AT    (t_optfm-kostl) '成本中心' CENTERED.
WRITE: AT /01(t_optfm-hkont) t_docit-hkont,           " 明細
       AT    (t_optfm-kostl) t_docit-kostl.
```

常用格式選項：

| 選項 | 效果 |
|---|---|
| `CENTERED` / `RIGHT-JUSTIFIED` / `LEFT-JUSTIFIED` | 指定寬度內置中／靠右／靠左（數值預設靠右、文字靠左） |
| `CURRENCY 'USD'`（或幣別欄位，如 `gs_booking-forcurkey`） | 依幣別小數位格式化金額——金額欄必加。後面接的是**幣別代碼**（字面值或 `CUKY` 型別欄位），不是另一個金額欄位；幣別的小數位設定在 `TCURX`（講義 21 §2.2） |
| `UNIT 'KG'`（或單位欄位，如 `gs_item-meins`） | 依單位小數位格式化數量——數量欄建議加。後面接**單位代碼**（字面值或 `UNIT` 型別欄位）；只去掉多出來、而且是 0 的小數，不四捨五入，單位的小數位設定在 `T006`（講義 21 §2.2） |
| `NO-GAP` | 下一個輸出緊貼、不留間隔 |
| `NO-ZERO` | 數字 0 顯示成空白 |
| `USING EDIT MASK '__:__'` | 自訂顯示遮罩 |

輔助指令：

```abap
ULINE.                 " 整行橫線
ULINE AT /1(77).       " 從第 1 欄畫 77 個字元寬的橫線
SKIP.                  " 空一行（SKIP 3. 空三行）
SKIP TO LINE 55.       " 游標直接跳到本頁第 55 行
NEW-PAGE.              " 強制換頁
```

`SKIP TO LINE n` 把游標移到**目前這一頁的第 n 行**，之後的輸出從那一行開始。用途是把某塊內容固定印在頁面的特定位置：講義 13 的 ZRFI0004 就是明細印完後 `SKIP TO LINE 55`，讓每一頁的簽核欄都從第 55 行開始，不管這頁明細有幾筆。n 如果超過 `LINE-COUNT` 的頁長（或小於等於 0），這個指令會被當成普通的 `SKIP`（官方文件 `SKIP`）。

### 2.1 中文字會被截掉：寬度要自己給足

`WRITE` 輸出一段文字時，保留的輸出寬度是**依字數**算的；但中文字（全形字）和 `→` 這類符號，在清單上每個**佔兩格**。字數算出來的寬度不夠放，文字結尾就會被截掉，而且**沒有任何錯誤訊息**。

實例（講義 10 的驗證程式 `ZR_TR10_HIDE_TEST`，2026-09-25 實測）：

```abap
WRITE / '測試 2：雙擊這一行 → SUBMIT 另一支報表'.
* 畫面顯示：測試 2：雙擊這一行 → SUBMIT 另一支報     ← 最後的「表」不見了

WRITE /(60) '測試 2：雙擊這一行 → SUBMIT 另一支報表'.
* 畫面顯示：測試 2：雙擊這一行 → SUBMIT 另一支報表   ← 指定寬度 60 格，完整顯示
```

**解法**：在 `WRITE` 用 `(寬度)` 明確指定輸出寬度，中文字一個抓**兩格**來估。排版欄位座標表時也一樣，中文欄位（名稱、說明）的寬度要以「字數 × 2」來規劃，不然會截字或擠壞後面的直欄。

**用程式算出實際佔幾格**：標準類別方法 `cl_abap_list_utilities=>dynamic_output_length` 會回傳一段文字在清單上實際佔的格數，中英混雜也算得準：

```abap
DATA: gv_text TYPE c LENGTH 40 VALUE '東捷資訊ABC',
      gv_len  TYPE i,
      gv_disp TYPE i,
      gv_pos  TYPE i.

gv_len  = strlen( gv_text ).                                        " 7：字數
gv_disp = cl_abap_list_utilities=>dynamic_output_length( gv_text ). " 11：4 個中文字 × 2 ＋ 3
gv_pos  = ( sy-linsz - gv_disp ) / 2.                               " 置中的起始欄
WRITE AT /gv_pos gv_text.
```

（2026-09-29 實測：`strlen` 回 7、`dynamic_output_length` 回 11，`LINE-SIZE 80` 時從第 34 格開始，標題正好置中。）`sy-linsz` 是目前清單的行寬，就是 `LINE-SIZE` 的值。

用途有兩種：

- **中文標題置中**：用 `strlen` 算會偏右，因為字數比實際格數少。ZRFI0004 的 `write_header` 為了算公司名稱的寬度，先把字串轉成繁中編碼（code page 8300）的位元組再數長度，繞了一大圈，用上面這個方法一行就夠。
- **把長文字切成兩行**：ZRFI0004 的 `split_sgtxt` 逐字呼叫 `dynamic_output_length` 累加格數，超過 50 格的部分放到第二行，所以中文內文不會被從中間截斷。

## 3. 頁首與頁尾（TOP-OF-PAGE／END-OF-PAGE）

搭配講義 10 的清單事件，標準版型長這樣：

```abap
TOP-OF-PAGE.
  WRITE: /1   '程式：', (20) sy-repid,
          50(20) '測試列印報表' CENTERED,
          108 '日期：', sy-datum.
  WRITE: /1   '使用者：', (18) sy-uname,
          108 '頁次：', (4) sy-pagno.
  ULINE AT /1(77).
  WRITE: /1  '|', 2(6)   '項次' CENTERED,
          9  '|', 10(20) '品名' CENTERED,
          31 '|', 32(10) '數量' CENTERED,
          43 '|', 44(14) '單價' CENTERED,
          59 '|', 60(16) '金額' CENTERED,
          77 '|'.
  ULINE AT /1(77).

END-OF-PAGE.
  ULINE AT /1(77).
  WRITE: /1 '審核：____________', 40 '製表：____________'.
```

- `sy-pagno`：目前頁次，頁首直接印。
- 觸發時機回顧：TOP-OF-PAGE 在每頁第一個 WRITE 前；END-OF-PAGE 在輸出踏進保留行區時。明細行數超過一頁，系統自動「頁尾 → 換頁 → 頁首」接下去。
- **`LINE-COUNT 65(3)` 的 65 是整頁總行數**，TOP-OF-PAGE 印的標題、SKIP 空行、明細、頁尾都算在內；`(3)` 是從這 65 行裡劃出最後 3 行給頁尾。以上面的版型為例：頁首 5 行＋頁尾 3 行，明細最多 65 − 5 − 3 = 57 行。
- ⚠️ **最後一頁通常印不出頁尾**：END-OF-PAGE 只在「輸出寫到保留區」時觸發，`NEW-PAGE` 不會觸發它（官方文件 `END-OF-PAGE` 明載）。最後一頁的明細沒填滿就結束了，頁尾就不會出現；只有一頁的短報表（如一張傳票）則完全沒有頁尾。實務上常見的改法是 `LINE-COUNT 65(0)` 不保留頁尾，改在輸出明細的 FORM 結尾自己印頁尾，印之前先寫 `RESERVE n LINES.`（n＝頁尾行數）：剩下的行數不夠 n 行就先換頁，頁尾才不會被拆到兩頁。代價是頁尾只印在報表最後，不是每頁都有。要**每頁都有頁尾**又不用 END-OF-PAGE，就得自己控制每頁印幾筆明細、在固定行號印頁尾——講義 13 第 6.1 節的傳票清單 ZRFI0004 就是這樣做（每頁 10 筆，`SKIP TO LINE 55` 印簽核欄與頁尾）。
- 「頁次 n / 總頁數」的**總頁數**要等全部輸出完才知道——回填技巧（READ LINE / MODIFY LINE）在期末實作講義 13 教。

## 4. 驗證方式

課堂上直接看螢幕清單即可（清單就是「虛擬的紙」）；要看實際分頁效果，故意產生超過一頁的測試資料（如 DO 150 TIMES 塞 150 筆），觀察每頁的頁首、頁尾與頁次遞增。列印預覽：清單畫面 → 列印，選對應格式（如 X_65_132）。

## 5. 常見錯誤與陷阱

| 症狀 | 原因 |
|---|---|
| END-OF-PAGE 完全不執行 | LINE-COUNT 沒寫保留行數 `(m)` |
| 前面各頁有頁尾，最後一頁沒有 | END-OF-PAGE 只在寫滿到保留區才觸發，最後一頁沒寫滿就不觸發——要每份報表結尾都有頁尾，改在程式裡自己印（見第 3 節） |
| 直欄歪掉對不齊 | 各行同一欄位的起始位置/寬度不一致——先畫欄位座標表 |
| 金額小數位錯 | 忘了 `CURRENCY`（有的幣別 0 位小數，如 JPY） |
| 每頁上方多一行程式名 | 忘了 `NO STANDARD PAGE HEADING` |
| 內容被折行 | 超出 LINE-SIZE——加寬或縮欄位 |
| 中文欄位寬度怪、文字結尾被截掉 | 全形字與 `→` 佔兩個輸出位置，但預設寬度按字數算——用 `(寬度)` 指定，中文以兩格估（見 2.1） |
